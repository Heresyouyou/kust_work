# 第三方 AI 调用 GeoKB：只需一行开头

> 版本 2026-10-23 · 权威副本 `https://sjck.kust.work/prompt.md`（服务端渲染，不会与接口脱节）

## 1. 你要发的就这一行

```text
先读 https://sjck.kust.work/ 的规则，然后回答：<你的问题>
```

例：

```text
先读 https://sjck.kust.work/ 的规则，然后回答：列举典型的燕山期成矿带，并给出可下载的原文 PDF
```

不用粘贴长提示词，不用自己写接口路径。

## 2. 为什么能这么短

完整规则（角色、执行顺序、五条契约、语料边界、引用格式、排错）已落在**站点根目录**
`https://sjck.kust.work/`，由 AI 自己读：

| 路径 | 给谁 | 作用 |
|---|---|---|
| `/`（=`/llms.txt`） | **AI** | 工作契约，唯一必读（2849 字符，一屏） |
| `/prompt.md` | 人 | 上面那一行 + 例子（585 B） |
| `/prompt-full.md` | 人 | 详版；仅当对方 AI 读不了网页时整段粘贴作系统提示 |
| `/llms-full.txt` | 备查 | 参数全表、字段说明 |

根目录契约规定的执行顺序：

1. `GET /health` → 先回报 `entries_total`（报不出 = 没真连上）
2. `GET /api/search?q=<关键词>&format=md&limit=5`
3. `GET /api/entry/<id>.md`
4. 本库撑不住 → 外扩到其他权威信源，逐条标注"（外源：来源名）"（见第 4 节）
5. 按契约第 1 节写、第 4 节格式引用 `[标题·刊名·年·id]`

## 3. 三条硬前提

1. **对方 AI 必须能联网发 HTTP**（联网搜索 / GPT Actions / MCP / 代码解释器 curl）。
   纯聊天模型只会假装引用——根目录第一条就要求它回报 `entries_total`，报不出即露馅。
2. **域名要能被对方环境访问**。若返回 `403 No policy rule matched`，是对方出口网关没白名单；
   本服务无鉴权、无 403 路由（自证：`curl -sI https://sjck.kust.work/health` 应见 `Server: Werkzeug`）。
3. **限流 120 次/60 秒/IP**，串行调用；条数用 `limit≤10` 控制，别靠翻页硬刷。

## 4. 本库储备不足时怎么办（契约第 1 节第 4 条）

本库是**文献语料**，不是普查全集。契约允许 AI 在两种情况下外扩：

| 情形 | 允许的做法 | 必须标注 |
|---|---|---|
| 检索为空 / 相关度明显偏低 | 先换 1 组同义词、英文术语重试；仍不足才外扩 | — |
| 确认本库覆盖不到（如教科书内容、最新未收录文献、区域普查数据） | 改用期刊原文、USGS、中国地质调查局、正式出版物等**权威来源** | 每条标"（外源：来源名）"，末尾单列"本库未覆盖" |

三条红线：**外源内容不得冒充本库结论**；**不得给外源编造条目 `id`**；**与本库冲突时以本库文献为准并说明分歧**。
引用样式：

```text
据《XXX》（MINERALS, 2024）paper-6011ea779131        ← 本库条目，带 id
据 USGS Mineral Commodity Summaries 2024（外源：USGS） ← 外源，不带 id
```

## 5. 常见误用

| 误用 | 后果 |
|---|---|
| 只发裸链接、不带问题 | AI 只复述契约或做摘要，不检索 |
| 自己另写接口路径塞进提示词 | 与根目录契约冲突，写错反而更糟 |
| 问"总结这个网站" | 它讲契约本身，不查库；要问**具体地学问题** |
| 以为库是普查全集 | 33 种期刊、89% 为 2021 后、532 条只有题录——契约第 3 节已写明边界 |
