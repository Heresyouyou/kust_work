## A. 区域定向清单（南亚东南亚，2026-10-27）

`scripts/history_manifest_region.py`，输出暂存区 `state/history_manifest_region.jsonl`。

24 种区域刊：JAES / JAES-X / Gondwana Research / Island Arc / Resource Geology / JGSI /
Vietnam JES / Indonesian J Geosci / Bull GSM / ActaGeolSinica + Tectonophysics / Chem Geol /
CMP / JMG / GeosciFront / IGR / JGS / GeolMag / JMPS / GCA / Precambrian / Terra Nova /
Geol Journal / Mineral Petrol。

**判据 = 区域词 × 核心学科词 双门槛**：
- 只提地名 → 会把水文/地震/滑坡/遥感捞进来；只有学科词 → 就是全球论文。
- 学科词分 `SEA_DISC_CORE`（权重 ≥3 才算进门）与 `SEA_DISC_AUX`（只加分）。
  平表 + 单一阈值不行，`Myanmar` + `basin` 会被误收。

**匹配器三处必须归一**（否则实测大批漏判）：
1. 复数 `(?:e?s)?` —— `amphiboles` / `granitoids` / `andesites` / `Himalayas`
2. 破折号 `[-–—]` —— `U–Pb` vs `U-Pb`
3. 重音 —— `mélange`

负向词只放**短语**：`flood basalt` 是地质词、`flood` 不是；`erosion` 在剥露研究里是核心。

**四个坑**：
1. ⚠️ 缓存键必须带 **ISSN**。刊名截断 24 字符会让 `JAES` 与 `JAES: X`、`JGSI` 与 `JGS`
   撞成同键，后者复用前者数据（实测 3603 + 2353 条挂错刊）。迁移脚本 `_migrate_cache.py`。
2. ⚠️ `load_stage_keys()` **不能读自己的暂存区**：重跑时与自己比会把全部条目判成重复，结果归零。
   只能读 `history_manifest_add10y.jsonl`。
3. ⚠️ CrossRef 的 `query.bibliographic` **不能用于地名检索**：查 `Myanmar porphyry copper`
   会把 Myanmar 整个丢掉，返回全球铜矿论文。只能「期刊全量枚举 + 本地标题精确过滤」。
4. 结果：38276 篇 → 双命中 3234 → 去重后 3221 条并入，清单 3149 → 6370。
   **merge 幂等**（2026-10-27 复跑只补 5 条漏网）。

## B. 入库与知识点（操作级）

- 每篇两次调用：摘要（**必然 0 缓存命中**，7,743 tok）+ 知识点（命中 72–95%）。
- 段落级筛选 C 方案 `text_prep.select_blocks()`（block@4500）：送 5,161 tok（−32%），
  数值召回 0.902 —— **召回靠 prompt 而非 token**。生产两处必须同改

  数值词边界必须 `(?<![A-Za-z0-9])`，否则 `May 2016` 被当 `201Ma`。
  见 `docs/最省token入库方案_20261020.md`。

- **模板权威 = `pdf_corpus_ingest.py` 525（英）/ 596（中）行**：
  - 英文：`Abstract / Key Content / Core Methods / Study Area / Application Scenarios`
    + `## 中文翻译` + `## 来源`

  - 英文条目的 `summary` 也必须英文。
  - `commit --no-facet` + 整批跑一次 `build_facet_index.py`。

- **知识点判据**：只问「能否用于团队今后研究」。复用五级 1.00/0.96/0.90/0.82/0.40
  （本区事实 ≤1 条）；**0–8 条，0 条合法**。

## C. 日期 / 标题口径（操作级）

- **`pub_date`** = 发布日期，**前端展示**（`pub_date or year`）。
  来源优先级：台账 `date`（按 `repo_path` 归一）→ 文件名前缀 `YYYY-MM-DD_` → `year`；
  `day == '01'` 归一为 `YYYY-MM`。**`updated`** 仅内部管理、不展示。
- **出版日期 = 在线首发日**（`Available online` / `Published online:` / `PUBLISHED`），
  不是卷期年 —— 有 56 篇年份比卷期年小。审计 `scripts/audit_pub_dates.py`。
  - ⚠️ 坑1：Elsevier 首页 `Available online` 可能在 **4000+ 字符**处 → 搜索窗口取 9000，别缩回 3000。
  - ⚠️ 坑2：中文刊数字常被字距拆开（`2 0 2 6 年 9 月`）→ 必须 `squeeze_digits()`。
  - ⚠️ 坑3：台账旧行只有年份精度（`YYYY-01-01`）时**以 PDF 实际日期为准**。
- **标题审计**：`scripts/audit_titles.py`（标题是否为 PDF 前两页正文子串）+ `fix_titles.py` 回填。
  - ⚠️ 改 `title:` **必须吃掉多行标量续行**（踩过：19 个文件 frontmatter 崩）。
  - ⚠️ PDF 标题块拼英文断行要补空格（`ofScheelite` 这类）。
  - ⚠️ 判命中前剔除行号与 `ACCEPTED MANUSCRIPT / REVISION N` 戳。
- **JSONL 铁律**：一律 `read_text().splitlines()`，**禁止** `for ln in open()` 后 `"\n".join()`
  （行尾 `\n` → 多出空行，2375 变 4749）。清理用 `scripts/normalize_ledger.py`。

## G. 队列节奏与清单自检（操作级）

- **节奏**：`PACE_GAP × --pace-scale(1.5)` + `DAILY_MAX` + 全局 `--gap 10s`。
- **空转休眠按 `wait2` 精确睡**（2026-10-28 改）：原 `max(PACE_TICK=20, wait2)`
  会让单源站时段（1,165 条岩石学报共用 `ysxb.ac.cn`、间隔 30s）实际间隔升到 40–60s。
  现为 `min(300, max(3, wait2+0.6))`；`wait2` 在 pace 分支恒 >0.5s，不会忙循环。
  ⚠️ 日志里「槽位全空」的秒数就是实际休眠时长，别按 PACE_TICK 估。
- **Springer 专档**：`TIMEOUT=90` 是单值全局超时，对 Springer 不够 —— 14 MB 的 PDF
  会在 90s 处**整段挂住**（一个字节都不来，不是慢），放宽到 `(15,180)` 后 7s 下完。
  判墙用落地页文案（`access this article`），`?pdf=button` / `%2F` 三种变体实测全无效。
- **限速状态按源站分文件**：`state/antibot_pace/<host>.json`（键名 `at`，原子写）。
  单文件 + Windows 字节锁实测形同虚设，必须分文件。
- **源站熔断**：连续失败 3 次 → 该社停 30min（期间不占槽位）。
- **清单热重载**：每 10min（无人在跑时）重 load + `revive_parked`。
- **清单自检**：丢半行 / 重复 id（原件留 `history_manifest.corrupt-*`）；
  整份不可读从 `.bak` 恢复；每 10min 轮换 `.bak`。
- **逐篇落盘**：每篇结束立刻 `save_manifest`（tmp+fsync+replace），
  失败分支**先写盘再打日志**；完成篇就地移除
  （老 bug：每轮重载导致 attempts 永远 0）。
- **单实例锁** `state/history_queue.lock`：调度器带 `GEOKB_QUEUE_LOCK=1`；
  手动跑被拒（rc=4，`--break-lock` 抢）。`--budget N` 到点先落盘再退。

**进度与实况排查**：`crawl_status.py` 出进度（CLI 与 5556 共用，8s 缓存）；
`/health`、`/llms.txt` 的 `entries_total` 取实时表值，`index_snapshot_entries` 只是索引快照。

## I. 近 20 年清单（`history_manifest_20y.py`）操作级细则

**五桶语义**（每次运行整组重写，`--stage-suffix _cn` 可单跑不覆盖主暂存区）：

| 桶 | 判据 | 注回命令 |
|---|---|---|
| `auto` | 非 SD、非冻结、有 handler | `--merge`（幂等） |
| `sd` | `10.1016` / SD 刊名表 | `--merge-backlog sd --force` |
| `blocked` | `source_freeze` 命中 | `--merge-backlog blocked --force` |
| `quota` | OUP（25 篇/天） | `--merge-backlog quota --limit 25` |
| `unsupported` | 无 handler | `--merge-backlog unsupported` |

**相关度三层**：`core`（score≥6）｜`ext`（3≤score<6 且命中 `ORE_KWS`）｜
`geo`（3≤score<6 且命中 `GEO_KWS` = ORE 237 + 构造 18 + 定年/矿物 20）。
`GEO_KWS` 里的词形**必须与 `score_loose()` 返回的规范名一致**（`U-Pb`/`Re-Os`/
`geochronology`/`锆石U-Pb`），写成小写永不匹配。`--geo-min-score 0` 退回 10 年口径。

**实测口径对比**（34 刊，2006-11~2026-10，114,997 条原始题录）：

| 口径 | 新增 | auto 可下 |
|---|---|---|
| 只用 core+ext（10 年口径） | 22,385 | 2,807 |
| 加 geo（成矿∪构造） | +3,422 | +252 |
| 再加定年/矿物词 | +1,638 | +175 |

**缓存**：`state/manifest_raw/v3_20y_<ISSN>_<起>_<止>.json` + `v3_20y_site_<刊名>_*.json`。
键**必须带 ISSN**（刊名截断 24 字符会让 JAES/JAES:X、JGSI/JGS 撞键）。
改阈值/词表只读缓存重跑，约 4 分钟，不联网。

**已知坑**：
1. `'- 窗口：%s ~ %s' % st['window']` → `TypeError: not enough arguments`
   —— `%` 右边是 list 时必须 `% tuple(...)`。
2. `load_stage_keys()` **不能读自己的暂存区**，否则重跑全部判重、结果归零。
3. **IGR 旧卷 `10.2747` 是死 DOI**：CrossRef 有完整元数据，但 doi.org 解析 404
   （Bellwether 时代未迁移到 T&F）。按标题回查会**映射回它自己**，不能当「修复」。
4. 中文四刊走官网枚举：`地学前缘`（earthsciencefrontiers.net.cn，3,721 条/226s）、
   `地质学报`（geojournals.cn，240 个期次页，实测 >90 分钟仍卡在网络等待）。

## J. 计划任务 / 黑窗判据（操作级）

## L. 录用稿（accepted manuscript）闸门（2026-10-29 定稿）

### L.1 为什么会有这一层

GSW 系的刊（AmMin `10.2138` / GSA `10.1130` / EconGeol `10.5382` /
MSA `10.2113` / JGSI `10.17491`）先挂 "Just Accepted"，此时 Crossref
**无 volume/issue**，源站 **只有录用稿 PDF**：首页带

```
This is the peer-reviewed, final accepted version for American Mineralogist …
The published version is subject to change. … in press.
```

且**全篇带行号**、无页码，"published version is subject to change"
→ 与正式版内容可能不同，**不能当定稿引用**（页码、版本一致性、统计口径全会偏）。

判据的**唯一实现**：`scripts/pdf_version_guard.py`
（`accepted` / `in_press` / `published` / `other`）。两条硬约束不能松：
**只扫第 1 页**（正式版卷期页码在首页页眉；参考文献里的 "in press" 在第 2 页起）
+ **只用强判据整句**（裸搜 `in press` 会成批误伤）。

### L.2 闸门放在哪（只放一处）

`journal_pdf_downloader.fetch_one()` 出口的 `_gate_version()`
（`D:/PostNews/.workbuddy/journal_pdf_downloader.py`）。

⚠️ 2026-10-27 的版本只接了 `history_queue._settle` 与
`daily_archive_papers.archive_one` 两处，**门户「下载 PDF」走的
`/api/journals/fetch-pdf` → `fetch_pdf` → `fetch_one` 完全没接**：
实测 NAS 里 AmMin 18 篇录用稿有 **10 篇是 `_fetch.pdf`**（09-24 ~ 10-23 门户按钮抓的）。
下沉到唯一出口后，日报 / 历史队列 / 门户按钮 / backfill 全部自动覆盖，
新增入口不会再漏。批量 CLI 的 `process()` 同样调 `_gate_version()`。

状态码：`accepted_version`（录用稿）/ `in_press`（无卷期 + in press）。
`history_queue._PERMANENT` 两者都算**永久失败**（重试不会变正式版），
3 次后停放、12h 自动复活再探。
