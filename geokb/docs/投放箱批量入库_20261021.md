# 统一投放箱：手动下载 PDF 批量入库（2026-10-21）

## 一句话

当天自动链路没拿到 PDF 的论文，**一律不入库**；用户手动下载后丢进
`D:/ZSK/geokb/inbox/papers`，每天 **12:01** 与 **18:01** 各批量入库一次，
自动归到 `by_journal/<期刊>/<年>/`，`kust.work/journals` 立即可下载。

覆盖**所有来源**，不只 ScienceDirect（SD 只是最典型的拿不到 PDF 的那一类）。

---

## 1. 口径变化（为什么要改）

| | 旧口径 | 新口径（2026-10-21 用户明确） |
|---|---|---|
| 没抓到 PDF 的论文 | 写 `metadata_only` 台账 + 写 `content/external-feed/` 题录，「先进库、以后补」 | **完全不入库**，不写台账、不建题目 |
| 补全文的方式 | 管线自动多渠道重试 + 「题录升级为 papers 条目」 | 用户手动下载 → 投放箱 → 批量入库 |
| 时点 | 每日管线随流程触发 | 固定 **12:01 / 18:01** 两次 |

**核心原则：知识库里只放「有全文」的文献。** 没下到的，宁可没有这条记录，
也不要留一条只有题目的空壳 —— 空壳会让 journals 页「已归档」判定出现
静默死角（历史实测：28 条题录里有 14 条落在 60 天窗口内，页面一直显示
「在线抓取」，补抓脚本又以为「已在 NAS」永不下载）。

## 2. 链路

```
用户手动下载 PDF
      ↓  另存到 D:/ZSK/geokb/inbox/papers/*.pdf（文件名随意）
[12:01 / 18:01  计划任务 GeoKB-InboxIngest]
      ↓
   ① 校验     %PDF- 魔数 / 200MB 上限 / pymupdf 可打开 / 写入满 120s 才处理
      ↓
   ② 探测     SHA-1、页数、前 3 页文本、PDF 元数据、最大字号块标题、DOI、PII
      ↓
   ③ 识别期刊 台账 → DOI 前缀 → ISSN → 刊名文本 → OTHERS（见 §3）
      ↓
   ④ 查重     sha1 / doi / pii / title；库内已有 PDF → 移 _duplicate/（不删）
      ↓
   ⑤ 落 NAS   by_journal/<期刊目录>/<年>/<日期>_<标题60>_manual.pdf
              写入后校验 size + SHA-1，不一致即回滚并报错
      ↓
   ⑥ 台账     state/papers_index.jsonl 追加 source=manual_inbox
              （先写台账，pdf_corpus_ingest 靠 repo_path 回查 journal/date）
      ↓
   ⑦ 入库     pdf_corpus_ingest.py --only → 摘要 + papers 条目
              kp_extract.py --sha      → 知识点
              index_one_entry          → FTS5 + 向量（秒级可检索）
      ↓
   ⑧ 清场     成功 → 删除本地 PDF（移动语义）；失败 → _failed/ 保留原件
```

单篇实测 **21 秒**（摘要 + 6 条知识点 + 索引）。

## 3. 期刊归属：四级识别 + 目录继承

### 3.1 刊名识别

| 级 | 依据 | 命中率来源 |
|---|---|---|
| ① | 台账已有记录（sha1/DOI/PII/标题命中） | 历史条目最准 |
| ② | DOI 前缀 `10.1016/j.<code>` | SD 地学刊全覆盖（OGR/Lithos/EPSL/Precambrian Res/Chemical Geology/Gondwana Res…） |
| ③ | 首页 ISSN | 20 个地学刊 ISSN 表 |
| ④ | 首页文本里出现已知刊名 | 台账 journal 值 + `PostNews/journal_ledger.json` |
| ⑤ | 都中不了 → `OTHERS` | 兜底，日志会标「未识别」 |

### 3.2 目录名继承（关键）

历史目录混用缩写与全称：`OGR` / `LITHOS` / `Earth and Planetary Science Letters`
并存，`ECONGEO` 与 `Economic Geology` 各有一份。硬编码刊名会造出**平行目录**。

做法：扫台账里每条有 PDF 的记录，取 `repo_path` 中
`by_journal/<目录>/` 的目录名与 `journal` 字段配对，**按篇数投票**取最多的那个。

实测反推结果（2026-10-21，台账 1458 条）：

| 台账 journal 值 | 反推目录 | 依据 |
|---|---|---|
| Ore Geology Reviews | `OGR` | 2/2 |
| Lithos | `LITHOS` | 2/2 |
| Earth and Planetary Science Letters | `Earth and Planetary Science Letters` | 3/3 |
| Mineralium Deposita | `Mineralium Deposita` | 64 篇 vs `MINDEP` 1 篇 |
| American Mineralogist | `American Mineralogist` | 20 篇 vs `AM` 6 篇 |

排除桶：`_feed_migration`、`_probe`、`Addition`、`OTHERS`（不是期刊，参与投票会污染）。

## 4. 台账字段

```json
{
  "title": "In-situ dolomite U-Pb dating constraints on ... Wanshan, South China",
  "url": "https://doi.org/10.1016/j.oregeorev.2026.107592",
  "doi": "10.1016/j.oregeorev.2026.107592",
  "journal": "Ore Geology Reviews",
  "date": "2026-01-01",
  "pdf_url": "",
  "repo_path": "S:/GeoKB/papers_repo/by_journal/OGR/2026/2026-01-01_..._manual.pdf",
  "size": 266045,
  "source": "manual_inbox",
  "sha1": "78d7d6fec395...",
  "eid": "paper-78d7d6fec395",
  "indexed_at": "2026-10-21T21:59:41",
  "uploaded_by": "folder",
  "file_name": "first-page_S0169136826004932.pdf"
}
```

- `journal` 写**规范刊名**（给人看、给门户展示），目录名另由 §3.2 决定。两者解耦。
- `url` 优先 DOI 链接；没有 DOI 用 SD 的 PII 文章页。这两个是 journals 页
  二级匹配（标题变体救生船）的依据。
- **不写 `upgraded_from`**：本链路不做「题录升级」，有 PDF 就入库。
- 同名同内容已存在于 NAS → 复用不重写（`reused`），台账照写。

## 5. journals 页下载

`/journals` 的下载按钮判据是 `journal_feed.is_pdf_entry(meta)`，只要求
台账 `repo_path` 含 `papers_repo/` 且后缀 `.pdf`。所以**写对台账即自动生效**，
不需要改前端，也不需要重启 5555（`load_ledger` 按 mtime+size 自动重建缓存）。

下载本身走 `GET /api/journals/pdf/<rel>`，支持 Range（喂自研阅读器 kpdf），
只放行 `papers_repo` 内的 `.pdf`。实测返回 `206` + `%PDF-`。

### Web 界面 `/geokb/inbox`（2026-10-21）

用户的下载工作表，替代手工翻 `state/journal_no_pdf.jsonl`。

```
浏览器  https://kust.work/geokb/inbox     （本机 http://127.0.0.1:5555/geokb/inbox）
三段式  ── 待下载       正常色，每行一个「打开下载页」+「标记已下载」
        ── 已下载待入库 整行灰掉（is-dl），只留「撤销」
        ── 已入库历史   移入下方，带「条目」「PDF」两个直达链接
```

| 层次 | 文件 | 职责 |
|---|---|---|
| 数据拼装 | `geokb/scripts/inbox_todo.py` | **唯一真源**。三源合并 + 三态判定 + 标记读写 |
| API | `geokb/server/app.py` `GET /api/inbox/todo`、`POST /api/inbox/mark` | JSON 出口；mark 只允许 `127.0.0.1` 调用 |
| 门户 | `Translate/modules/geokb_public/routes.py` `/inbox`、`/inbox/data.json`、`/inbox/mark` | 渲染 + 转发，不自己算 |
| 模板 | `Translate/modules/geokb_public/templates/geokb_public/inbox.html` | 骨架 + 60s 轮询 + 前端渲染 |
| 测试 | `Translate/inbox_dom_test.js` | Node DOM 垫片，45 项断言 |

三源（都是「自动流程试过但没拿到全文」）：

| 源 | 文件 | 页面标签 |
|---|---|---|
| A | `state/journal_no_pdf.jsonl` | 今日未下到 |
| B | `state/history_manifest.jsonl` 里 `status=parked`（连试 3 次） | 重试失败 |
| C | `state/papers_index.jsonl` 里 `source=metadata_only` | 历史遗留 |

三态判定（**顺序即优先级**，与 §4「已归档判据」同一条规则）：

1. 台账 `repo_path` 含 `papers_repo/` 且 `size>0` → **已入库**（进历史，`origin=auto`）
2. 投放箱 PDF 探测出同 DOI / 同标题 → **已下载**（自动变灰，无需手工勾）
3. `state/inbox_marks.json` 里有人工勾选 → **已下载**（扫描件无 DOI 时的兜底）
4. 其余 → **待下载**

设计取舍：

- **标记落服务端**（`state/inbox_marks.json`），不落 localStorage
  —— 换设备/换浏览器看到同一份勾选。
- **探测有预算**：单次最多新解析 25 个 PDF（3 页文本），其余靠
  `state/inbox_todo_probe.json` 的 mtime+size 缓存，或下一轮补
  —— 防止一次投几十篇把首屏请求拖超时。
- **5556 缓存 45s**，指纹 = 3 个 jsonl + 标记文件 + 投放箱 PDF 的 mtime；
  `mark` 后立即置空强制重算，所以勾选是即时生效的。
- 入库成功后**不需要任何回写**：台账新增 `manual_inbox` 记录 + 投放箱文件被移走，
  下一个轮询周期页面自己就挪到历史区。

改动这条链要同步的三处（**改一处就得改三处**，否则页面与命令行各说一个数）：
`inbox_todo.snapshot()` → 5556 端点 → `inbox_ingest.show_todo()`。

### 计划任务

`GeoKB-InboxIngest`：每天 `12:01`、`18:01`，`LeastPrivilege` + `InteractiveToken`，
`MultipleInstancesPolicy=IgnoreNew`（上一轮没跑完不会叠跑），
`StartWhenAvailable=true`（关机错过后开机补跑），执行时限 2 小时。
