# 近 5 年目标期刊历史文献补爬计划

> 定稿：2026-10-18 ｜ 执行体：`scripts/history_manifest.py`（一次性生成清单）
> + `scripts/history_queue.py`（逐条消费）+ `scripts/history_queue_loop.py`（常驻调度）

## 一、目标与边界

| 项 | 口径 |
|---|---|
| 范围 | `journals.json` 里 14 种目标期刊（国内 6 + 国际 8） |
| 时间窗 | 近 5 年（滚动，本次 2021-10-19 ~ 2026-10-18） |
| 相关性 | `journal_filter.calc_relevance_score(title) >= 6`（团队既有口径：三江/西南三江等区域 + Cu-Mo-Sn-W-Au-PbZn 矿种 + 斑岩/矽卡岩/热液/造山型等矿床类型 + 成矿理论/找矿预测） |
| 去重 | 已下载（台账 `repo_path` 指向 papers_repo 的 PDF）+ 已入库（`content/papers/*.md`）+ 同批内重复 |
| **清单性质** | **一次性快照**。生成后只消费、不重建。日常新增论文由既有推送管线处理，与本清单互不干扰 |

**明确不在本清单范围内**：当天/近日新更新的期刊论文——那是 `journal_auto_push.py`
（TRAE 定时 05:00/13:00/19:00/23:00）+ `daily_run.py` 的职责。

## 二、清单怎么来（数据源分层）

| 层 | 期刊 | 手段 | 备注 |
|---|---|---|---|
| CrossRef 精确日期 | EPSL、Geology、Economic Geology、Mineralium Deposita、Ore Geology Reviews、Journal of Petrology、Lithos、American Mineralogist、地球科学、矿物岩石地球化学通报 | `api.crossref.org/journals/{ISSN}/works` + cursor 分页 | 日期可精确到日 |
| 官网按期卷枚举 | 矿床地质、地学前缘、地质学报、大地构造与成矿学 | 各刊过刊页（见下） | 这 4 本 CrossRef 未登记或只收英文版 |

官网枚举的实测入口（2026-10-18 验证可用）：

- **矿床地质**：`issue_list.aspx?year_id=YYYY&quarter_id=N` → `view_abstract.aspx?file_no=YYYYIINN`
- **地学前缘**：`/CN/Y{年}/V{卷}/I{期}`（卷号 = 年 − 1993）→ `a.txt_biaoti`
- **地质学报**：`/dzxb/article/issue/{年}_{卷}_{期}`（卷号 = 年 − 1926）→ `article/abstract/*`
- **大地构造与成矿学**：需 ASP.NET 会话；`getThisIssuePaperInfo.ashx?y=YYYY&i=NN`
  ⚠️ **`i` 必须两位**（`05` 而非 `5`），否则返回「暂无内容」

## 三、清单长什么样

`state/history_manifest.jsonl` —— 一行一篇，字段：

```json
{"id":"hm-xxxx","journal":"Lithos","title":"...","url":"https://doi.org/...",
 "doi":"10.1016/...","date":"2023-05-01","year":"2023","volume":"","issue":"",
 "score":9,"matched":["skarn","tungsten"],"source":"crossref",
 "reach":"elsevier","reach_p":0.25,
 "status":"pending","attempts":0,"last_error":"","added_at":"..."}
```

| 字段 | 说明 |
|---|---|
| `score` | 相关度分（≥6 才进清单） |
| `matched` | 命中的团队方向关键词（可解释为什么收录） |
| `reach` / `reach_p` | 源站可达性预判，决定爬取顺序 |
| `status` | `pending` 待办 / `parked` 停放（连续 3 次失败） |
| `attempts` | 已尝试次数 |

配套文件：

- `state/history_manifest.html` —— **人读清单**，浏览器直接打开，可按期刊/年份筛选、关键词搜索
- `state/history_manifest_stats.json` —— 生成时统计快照（分期刊/年/分数/源站）
- `state/history_done.jsonl` —— 已完成记录（append-only，留痕）
- `state/history_queue_state.json` —— 队列当日进度

## 四、爬取顺序：先易后难

`reach_p` 排序（高→低），同组内再按相关度降序、年份降序：

| reach | 含义 | 经验成功率 |
|---|---|---|
| `cn_site` 0.92 | 中文刊官网 / 国内 DOI | 高（直链 PDF） |
| `springer` 0.65 | Springer（Mineralium Deposita） | 中，部分 OA |
| `gsw` 0.50 | GSA / geoscienceworld | 低-中，付费墙多 |
| `seg` 0.45 | Economic Geology | 低 |
| `oup` 0.40 | Journal of Petrology（Cloudflare） | 低，需浏览器验证 |
| `elsevier` 0.25 | EPSL / OGR / Lithos（ScienceDirect） | 近零（四渠道全 403，无仓储副本） |

**为什么先下能下的**：让清单持续缩短、早期就有正反馈；Elsevier 那批会以极低成本
快速失败（每篇几秒）并逐轮转 `parked`，不会长期占着队列。

## 五、时段策略（2026-10-21 改：只下载阶段全天候）

> **当前口径**：自动爬取只下载不入库（`ingest_policy` 的 history scope 关），
> 不调 DeepSeek API → **全天候 24h 爬取，不受任何时段限制**。
> 下面这张表只在「恢复自动入库」时才生效，保留备查。

| 场景 | 历史清单 | 依据 |
|---|---|---|
| **只下载不入库（当前默认）** | ✅ **全天候 24h** | 不调 API，没有卡时段的理由 |
| 入库模式（history scope 开） | 见下表 | 入库要调 LLM → 受 API 高峰禁令约束 |

入库模式下的旧规则（2026-10-18 定稿，现已挂起）：

```
18:05 ─────────────────────────── 次日 07:00 ────── 09:00 ──────────── 18:05
   ↑ 历史清单爬取窗口（13 小时）      ↑ 当天更新优先   ↑ 业务高峰，静默
```

| 时段 | 历史清单 | 当天更新管线 | 依据 |
|---|---|---|---|
| 18:05 – 24:00 | ✅ 每 18 分钟一轮 | 正常 | DeepSeek 低谷窗口（铁律允许段） |
| 00:00 – 07:00 | ✅ 每 18 分钟一轮 | 正常（05:00 那轮） | DeepSeek 低谷窗口 |
| **07:00 – 09:00** | ❌ **完全让位** | **优先保障** | 用户明确要求；且 09:00 起进 API 高峰 |
| 09:00 – 18:05 | ❌ 静默 | 正常（13:00 那轮） | 业务 + API 双高峰 |

时段判定写死在 `history_queue.window_ok()`，**不依赖调用方自觉**——即使定时任务
在 08:00 误触发，脚本也会直接返回 2 并说明原因。
**注意**：只下载模式 (`ingest_policy.enabled('history') == False`) 下该判定直接放行，
返回「全天候爬取，不受时段限制」。

## 六、单篇流水线（一篇走完全链才出清单）

```
① 台账已有 PDF？──是──→ 跳过下载
        │否
        ↓
② fetch_pdf（handler → OA 多渠道 → 浏览器验证）  失败 → attempts+1，留清单
        ↓
③ 落 NAS（papers_repo/by_journal/<刊>/<年>/…_hist.pdf）
        ↓
④ 登记台账 papers_index.jsonl（含 eid）
        ↓
⑤ 入库：pdf_corpus_ingest.py --only <pdf>（DeepSeek 提取 papers 词条）
        ↓
⑥ 拆知识点：kp_extract.py --sha <sha1>（最多 6 条 kpoint）
        ↓
⑦ 三步全绿 → 写 history_done.jsonl + 从清单物理移除
```

- **幂等**：任一步中断后重跑，已存在的 PDF / 词条 / 知识点会跳过，不会重复消费 API。
- **失败分级**：`attempts < 3` 下轮重试；`>= 3` 转 `parked`（不再自动取，可 `--include-parked` 手动捞）。
- **索引刷新**：papers/kpoints 词条即时落盘；`rebuild_index.py` 由守护/每日管线统一重建
  （逐篇重建全库代价过高）。

## 七、节奏与产能

| 参数 | 默认 | 说明 |
|---|---|---|
| 每轮篇数 | 1 | `--limit` 可调；常驻调度器固定逐篇 |
| 篇间隔 | **3 分钟** | `--gap 180`，从上一篇结束算起；压住单 IP 请求密度防验证 |
| 运行时长 | **24 小时/天** | 只下载不入库阶段；入库模式退回 13 小时/天（18:05→07:00） |
| 单篇周期 | ≈ 4.8 分钟 | 实测下载 1.8 分钟 + 节流 3 分钟（样本 12） |
| **产能** | **≈ 150 篇/天** | 全天候；入库模式约 150 篇/夜 |

按此节奏，1838 篇可执行清单约 **6 天**消化完（全天候）；`parked` 项另算。

## 八、怎么跑

```bash
# 1) 一次性生成清单（已完成后不必再跑；想刷新才跑，会覆盖）
D:/ZSK/geokb/venv/Scripts/python.exe D:/ZSK/geokb/scripts/history_manifest.py

# 2) 看进度（随时可看）
D:/ZSK/geokb/venv/Scripts/python.exe D:/ZSK/geokb/scripts/history_queue.py --status

# 3) 手动跑一篇（篇间自动等 3 分钟）
D:/ZSK/geokb/venv/Scripts/python.exe D:/ZSK/geokb/scripts/history_queue.py --limit 1

# 4) 常驻调度（推荐：后台无窗口，逐篇 + 3 分钟节流，只下载阶段全天候）
#    双击 tools\start_history_queue.bat 即可（Windows 资源管理器里双击）
#    或命令行：
D:/ZSK/geokb/venv/Scripts/pythonw.exe D:/ZSK/geokb/scripts/history_queue_loop.py
```

停止常驻：`state/history_queue_loop.pid` 里是 pid，
`taskkill /PID <pid> /F`。

### 关于「谁能拉起常驻进程」

⚠️ **不要从 agent 会话 / 终端里 Popen 启动它**：本机作业对象（Job）会在父进程退出时
回收所有子进程，`DETACHED_PROCESS | CREATE_BREAKAWAY_FROM_JOB` 也照样被回收
（2026-10-18 实测 6 次全部被杀）。可靠路径只有两条：

1. **用户双击** `tools\start_history_queue.bat`（一次性动作，之后长期常驻）；
2. **由 GeoKB 守护进程托管**：`geokb_daemon.py` 已加 `EXTRA_PROCS` 看护
   （读 `state/history_queue_loop.pid`，进程不在就拉起）。守护进程下一次重启后
   自动生效，此后调度器随守护一起长生不老。

**兜底**：`journal_auto_push.py` 每轮结束会调一次 `history_queue.py --limit 4`
（检测到常驻调度器在跑则让位），保证即使常驻进程没起，清单也在缓慢推进。

## 九、与既有管线的关系（互不干扰）

| | 触发 | 职责 | 会不会抢资源 |
|---|---|---|---|
| 当天更新 | `journal_auto_push` 4 次/日 + `daily_run` | 抓当天新文 → 归档 → 海报 → 推送 | 只下载阶段**不再让位**；入库模式 07:00-09:00 强制让位 |
| 历史清单 | `history_queue_loop` 常驻 | 5 年存量逐条补爬 | 只下载阶段**全天候 24h**；入库模式 18:05-07:00 |

两者共用 `papers_repo` / `papers_index.jsonl` / `content/`，靠**标题+DOI+URL 三重去重**
避免重复下载；`fetch_pdf` 内部有源站串行与限流，不会把 IP 打挂。

## 十、风险与已知限制

1. **Elsevier 三刊（EPSL / OGR / Lithos）基本拿不到**：2026-10-18 实测四渠道全 403、
   CrossRef/Unpaywall/OpenAlex 无仓储副本。这些条目会走完 3 次重试转 `parked`，
   属于"已知不可得"，不影响其他刊。
2. **OUP / GSA 受 Cloudflare 与订阅权限双重限制**：浏览器验证通道能过挑战，
   但付费文 PDF 直链会回落文章页（判 `paywalled`），成功率低。
3. **中文刊官网无日期字段**：只能精确到"年-期"，清单里 `date` 为 `YYYY-MM-01`（估算），
   不影响下载与入库。
4. **大量 LLM 调用**：每篇 2 次（入库提取 + 知识点抽取）。全部落在 DeepSeek 低谷窗口
   （18:01-24:00 / 00:00-08:59），符合既有铁律；07:00-09:00 不跑也正好避开 09:00 高峰。
5. **NAS 台账不要写成 SMB 独占锁**：`papers_index.jsonl` 用本地副本
   `state/papers_index.jsonl`，不要改回 `S:/` 路径。
