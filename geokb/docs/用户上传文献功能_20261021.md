# GeoKB 用户自定义上传文献功能 — 需求固化与实现记录

> 固化时间：2026-10-21 09:00（北京时间）
> 目的：把原始提示词逐字存档，防止对话超长后需求漂移；后续实现以本文「验收标准」为唯一准绳。

## 一、原始提示词（逐字存档，未改动）

> 在知识库模块中，实现一个用户自定义上传文献的功能入口。功能需满足以下要求：
> 1. 上传与补充信息：提供上传入口，支持用户上传 PDF 文件，并允许用户补充自定义文献信息（如标题、作者、关键词、摘要、标签等）。
> 2. 查重匹配：PDF 上传后，系统应先匹配知识库中已有文献，匹配维度需明确（例如基于标题、DOI、文件内容特征或哈希）。若已存在相同论文，直接返回该文献的库内链接，不再执行后续上传。
> 3. 存储与入库：若库中无相同文献，则将 PDF 上传至 NAS，并专门存放用户上传文献；上传完成后立即执行文献解析和入库操作，提取元数据并建立索引、拆分知识点。
> 4. 归属规则：在 NAS 中新建 "Addition" 文件夹，用户上传的文献不归属到任何期刊，仅存放于 "Addition" 文件夹中。
> 请给出该功能的完整实现，涵盖上传交互、查重逻辑、NAS 存储路径规划、解析入库流程及异常处理。

## 二、需求拆解（功能清单）

| # | 用户故事 | 优先级 | 验收标准 |
|---|---------|--------|---------|
| F1 | 作为用户，我能在知识库页面找到上传入口，上传 PDF 并补充标题/作者/关键词/摘要/标签 | P0 | `/geokb/upload` 页面可用；表单字段齐全；仅接受 `.pdf`（magic `%PDF` 校验），超限/类型错误有明确提示 |
| F2 | 作为用户，上传后系统先查重，已存在时直接给出库内链接、不再上传 | P0 | 查重维度显式声明（见下）；命中返回 `/geokb/entry/<eid>` 直达链接；不落 NAS、不写台账、不调 LLM |
| F3 | 作为用户，库中没有时 PDF 存到 NAS 的 Addition 文件夹，并立即解析入库（元数据+索引+知识点） | P0 | 路径 `<pdf_root>/Addition/<年>/<日期>_<安全标题>.pdf`；台账 `journal=Addition`、`source=user_upload`；入库后 `/geokb/entry/paper-<sha1前12>` 与知识点 `kp-<sha12>-*` 可检索 |
| F4 | 作为用户，上传文献不归属任何期刊 | P0 | 台账与条目 frontmatter 的 `journal` 均为 `Addition`，不带入 by_journal 任何子目录 |
| F5 | 作为用户，上传过程有进度反馈，失败有原因与重试入口 | P1 | 轮询状态：排队→解析→入库→拆知识点→建索引；失败保留原因；扫描版 PDF 降级为「仅题录」并明示 |
| F6 | 作为运维者，异常（NAS 不可达、PDF 损坏、锁占用、API 故障）不产生半成品状态 | P1 | 任一步失败：要么整体回滚记录，要么明确标注「PDF 已落盘/台账已写」的补救路径；不写垃圾数据 |

### 查重维度（显式声明，按优先级）

| 维度 | 判据 | 数据来源 | 命中后动作 |
|------|------|---------|-----------|
| D1 文件哈希 | 上传文件 SHA-1 与库内记录**逐字节相等** | 台账 `sha1` 字段（新记录必写）；候选记录的 NAS 文件实时计算 | 返回库内链接，维度标记 `sha1` |
| D2 DOI | 归一化 DOI 精确相等（去 `doi.org/` 前缀、转小写、去尾部标点） | 用户填写 / PDF 前 3 页正文提取 / 台账 `doi`、`url` 字段 | 返回库内链接，维度标记 `doi` |
| D3 标题 | 归一化标题相等（小写、仅保留字母数字）；长标题（≥70 字符）允许前 80 字符相等且唯一 | 台账 `title` | 返回库内链接，维度标记 `title` |
| D4 内容条目 | `content/papers/paper-<sha1前12>.md` 已存在（已入库过同一文件） | content 目录 | 返回库内链接，维度标记 `content_entry` |

D1 对 Legacy 记录（无 `sha1` 字段）的补偿：D2/D3 找到候选后，实时计算候选 NAS 文件 SHA-1 与上传文件比对——相等判重（同一文件），不相等则视为「同题不同版」，允许上传并在结果中注明。

## 三、设计（实现前定稿）

### 3.1 架构与数据流

```
浏览器 /geokb/upload
   │  POST multipart（PDF + 元数据）
   ▼
5555 geokb_public.routes（Flask/waitress，threads=8）
   │  ① 落 spool 临时区 state/upload_spool/<task_id>/
   │  ② 后台线程 subprocess 调 scripts/user_upload.py（geokb venv）
   ▼
scripts/user_upload.py（核心逻辑，CLI 可独立复用）
   │  D1-D4 查重（台账 + content 目录）
   │  ├─ 命中 → status=duplicate + link，结束（不落 NAS）
   │  └─ 未命中 → 存 NAS Addition/<年>/<日期>_<标题>.pdf
   │            → 台账追加（sha1/journal=Addition/source=user_upload/用户元数据）
   │            → pdf_corpus_ingest.py --only（DeepSeek 摘要提取，写 content/papers）
   │            → kp_extract.py --sha（DeepSeek 拆知识点，写 content/kpoints）
   │            → index_one_entry.py ×N（FTS5 + 向量，秒级可见）
   ▼
状态文件 spool/<task_id>/status.json（前端 2s 轮询）
```

### 3.2 NAS 存储路径规划

```
S:/GeoKB/papers_repo/
├── by_journal/<期刊>/<年>/<日期>_<标题>.pdf     # 既有：期刊论文
└── Addition/<年>/<日期>_<安全标题>.pdf          # 新增：用户上传，不归属期刊
```

- 根路径统一走 `scripts/paths.py::pdf_root()`（环境变量 > config/paths.yaml > S: > UNC > 旧路径），不硬编码。
- 文件名：`<日期>_<safe_name(标题,60)>.pdf`，与 by_journal 命名风格一致；`safe_name` 过滤 `\/:*?"<>|`。
- 台账 `repo_path` 存绝对路径（与既有记录一致），条目 frontmatter `sources[].path` 存 `papers_repo/Addition/...` 相对路径（pdf_service 解析约定）。

### 3.3 台账记录格式（state/papers_index.jsonl 追加行）

```json
{
  "title": "用户标题或PDF提取标题",
  "url": "用户提供的来源URL（可空）",
  "doi": "10.xxxx/yyyy（可空）",
  "journal": "Addition",
  "date": "2026-10-21",
  "pdf_url": "",
  "repo_path": "S:/GeoKB/papers_repo/Addition/2026/2026-10-21_标题.pdf",
  "size": 1234567,
  "source": "user_upload",
  "sha1": "<40位hex>",
  "eid": "paper-<sha1前12>",
  "indexed_at": "2026-10-21T09:00:00",
  "authors": ["Zhang San", "Li Si"],
  "keywords": ["skarn", "tungsten"],
  "abstract": "用户补充摘要（可空）",
  "tags": ["矽卡岩", "白钨矿"],
  "remarks": "用户备注（选填，仅非空时写入）",
  "uploaded_by": "web"
}
```

> **2026-10-21 交互定稿（用户口径）**：默认用户只需上传 PDF + 一行选填**备注**
> （`remarks`）；标题/作者/DOI/关键词/标签/日期/链接/摘要全部收进「拓展填写」折叠区
> （`<details>`，默认收起），不填则从 PDF 自动解析，**展开填写了则以用户值为准**。
> `remarks` 全链路落点：台账行 `remarks` 字段（非空才写）→ 条目 frontmatter
> `remarks:` → 条目「文献信息 / Document Information」区块「备注：」行。

### 3.4 入库管线复用（不重复造轮子）

| 阶段 | 复用 | 说明 |
|------|------|------|
| 文本提取 | `pdf_corpus_ingest.extract_text` | 缓存 `state/text/<sha1>.txt` |
| 摘要提取 | `pdf_corpus_ingest.ds_extract`（DeepSeek） | 失败自动 `fallback_extract`（正则抽摘要） |
| 条目生成 | `pdf_corpus_ingest.write_entry`（加 `user_meta` 参数） | 用户元数据优先于 LLM 提取；HTML 转义防注入 |
| 知识点 | `kp_extract.py --sha` | 最多 6 条，证据行号，T3 降权 |
| 索引 | `index_one_entry.py` | ~0.6s/条，DELETE+INSERT 幂等 |

**与既有锁的协作**：`pdf_corpus_ingest` 有 `state/pdf_ingest.lock`（历史队列夜间逐篇消费同用此锁）。上传入库遇锁占用 → 状态置 `queued`，每 30s 重试，最长等待 20 分钟，超时置 `failed` 并保留补救入口（`ingest_policy.py --run` 同款 pending 清单）。

### 3.5 异常处理矩阵

| 异常 | 检测 | 处理 |
|------|------|------|
| 非 PDF / magic 不符 | 扩展名 + 头 5 字节 `%PDF` | 400 拒绝，不落盘 |
| 超过大小上限（100MB） | spool 时 stat | 413 拒绝 |
| PDF 损坏打不开 | pymupdf.open 抛错 | task failed，spool 保留 48h |
| 扫描版（无文本层） | extract 后 <1500 字符 | 仍建条目（用户题录优先），kp 标记 skipped，状态 `partial` |
| NAS 不可达 | 目录创建/写探针失败 | task failed，明示「PDF 未入库，请检查 NAS」 |
| 台账写失败 | append 抛错 | 明示「PDF 已落盘 <path>，仅台账失败」，保留 PDF |
| 入库锁被占 | pdf_ingest.lock pid 存活 | queued 等待重试（≤20min） |
| DeepSeek 故障 | pdf_state.jsonl status=failed | task failed，可一键重试（复用同一 eid，幂等） |
| 用户元数据含 HTML | 写入前 `html.escape` | 转义后入库，防 XSS |
| 并发上传同一文件 | spool 内 sha1 内存锁 + 台账二次校验 | 后者判重返回链接 |
