# 最省 token 的入库方案（2026-10-20）

> 前提：**入库质量只能升不能降**。以下全部为本机真实数据实测，含一次失败的尝试。

---

## 一、先把账算准：钱花在哪

数据源：`state/pdf_state.jsonl`（273 篇，摘要任务）+ `logs/kp_ingest.jsonl`（1897 次，知识点任务）。

| 项目 | 实测 |
|---|---|
| 摘要任务输入（**首次调用，全价**） | 均 **7,743** tok · 命中 **0.9%** |
| 摘要任务输出 | 均 ~450 tok |
| 知识点任务输入（**第二次，命中缓存**） | 均 7,500 tok · 命中 **72.4%**（近期 95%） |
| 知识点任务输出 | 近期均 ~1,200 tok |

按官方计价折成每篇成本权重：

| 成本项 | 权重 | 占比 |
|---|---:|---:|
| **摘要任务·输入（全价）** | 1,161 | **52.1%** |
| **知识点·输出** | 720 | **32.3%** |
| **摘要任务·输出** | 270 | **12.1%** |
| 知识点·输入未命中（5%） | 56 | 2.5% |
| 知识点·输入命中（95%） | 21 | 1.0% |
| 合计 | 2,229 | 100% |

**结论**：64% 的钱花在「摘要任务」上，而它是同一篇里第一个被调用的，**天然拿不到缓存**。知识点任务因接着跑、前缀相同，输入已只占 3.5% —— 缓存这条路已经走到头。

> ⚠️ 纠正旧结论：此前记录的「缓存命中率 92.4%、总成本 −55%」是实验脚本对**同一篇连调两次**的结果，不是生产。生产里第一个任务必然 0 命中。缓存改造没白做（省下了知识点任务的输入），但它不再是下一步杠杆。

## 二、三条降本路径（按风险从低到高）

### A. 摘要不让 LLM 抄 —— 省 12%，**零质量风险**

现在英文模板要求 `abstract_en: "verbatim from the paper"`。实测 62.7% 篇目有该字段、中位 **448 tok**，去掉空白后 **100% 能在原文逐字检索到** —— 模型在花 output 的钱，重打一遍 PDF 里已有的文字。

改为本地正则抽取（`Abstract` / `A B S T R A C T` / `摘要` 到 `Keywords`/`Introduction` 止）。抽样 40 篇：29 篇完全一致、1 篇部分一致、10 篇抽不到（多为原文本身无摘要）。抽不到的用模型本来就会输出的 `key_content_en` 顶替，**不额外调用**。

### B. 字段瘦身 + 知识点限条 —— 省约 20%，**低风险**

- 英文模板 15 个字段里 8 个是「中文字段对照」，只用于 UI 小字注解。`text_prep.TAG_SYNONYMS` 已有受控词表，可本地映射；只保留 `title_zh` + `key_content_zh`（这两个必须模型翻）。
- 知识点现在固定要 6 条、输出 1,200 tok。改为 **3–5 条、每条 ≤80 字、必须带具体证据（数值或 L 行号）**，删掉「具有重要意义」这类泛化条目 → 输出降到 ~800。条数少了，信息密度反而高。

### C. 输入压缩（段落级筛选）—— **已达标，可以上生产**

思路是「按信息量挑内容」替代「头部 65% + 结论段」的字符截断，因为论文事实
（年龄、品位、同位素）散在结果中段和表格里，恰好落在被砍掉的部分。

#### C1 走过的弯路：句子级筛选（已废弃）

第一版按「单句」打分取舍。文本侧看着很好，但落地就崩：

| 指标 | 句级筛选 @4500 |
|---|---|
| 文本数值覆盖 | 77%（中位） |
| 输入 tok | −36% |
| **输出数值召回** | **0.629**（要求 ≥0.90 ❌） |

**根因**：一个 3 句的论证被选中第 1、3 句、丢掉第 2 句，模型看到的是互不衔接的
断言，于是倾向概括而不引用具体数字。**文本覆盖率 ≠ 输出召回率** —— 本次最重要的教训。

#### C2 正确做法：把原子单元从「句」放大到「段落」

`text_prep.select_blocks()`，三处关键设计：

1. **先修折行**：`state/text` 里的「行」是 PDF 排版折行（中位行长 22–60 字符），
   一个自然段跨 3–10 行。若不先拼回段落，段落级筛选会退化成「挑折行」，切点全在句中
   —— 这正是 C1 失败的原因。`reflow_paragraphs()` 按「行末句末标点 + 满行」「短行」
   「小节编号开头」三条依据断段，中文折行不加空格。
2. **整段取舍**：段内逻辑完整，不拆散。超长段落（>1100 字符）才在段内降级，
   且只取**连续前若干句**，不跳选。
3. **补缝 + 省略标记**：被跳过的孤立单块在预算允许时补回；未选中区间插入 `[…略…]`，
   让模型明确知道这是节选。

**文本侧（30 篇离线，同预算 4,500）**：

| 方案 | 文本覆盖 | 数值覆盖 均值 | 中位 | **最低** |
|---|---:|---:|---:|---:|
| head+tail @4,500 | 0.249 | 0.157 | 0.088 | **0.00** |
| 句级筛选 @4,500 | 0.239 | 0.669 | 0.753 | 0.00 |
| **段落级 @4,500** | **0.346** | **0.771** | 0.781 | **0.46** |
| head+tail @10,000（现行生产） | 0.543 | 0.347 | 0.250 | 0.04 |

即：**用现行生产一半的 token，拿到 2.2 倍的数值覆盖，且没有崩盘篇目**。

**API 对拍（16 篇固定样本池，与旧方案输出逐项比）**：

| 指标 | 块级@4500 | 块级@4500 + 数值约束 |
|---|---:|---:|
| 送入文本 tok | 7,566 → 5,161（**−32%**） | 同左 |
| 输出 tok | 654 → 728（+11%） | 729 |
| JSON 失败 | 0/16 ✅ | 0/16 ✅ |
| 字段非空率 | 0.944 → 0.958 ✅ | 0.944 → 0.944 ✅ |
| **关键数值召回** | 0.693 ❌ | **0.902 ✅**（中位 1.000） |
| key_content 重叠 | 0.648 ✅ | 0.584 ⚠️ |
| tags 重叠 | 0.692 ✅ | 0.717 ✅ |

#### C3 决定性的那一句 prompt

数值召回 0.693 → 0.902，靠的不是更多 token，而是**在 prompt 末尾加一条输出约束**
（已写入生产模板 `pdf_corpus_ingest.py` 的 ZH/EN 两个模板）：

> key_content 中必须写出原文给出的关键数值，保留原数值与单位（如 385±40℃、251±7℃、
> -1.58‰、120 Ma、3.5 g/t、12%），不要用「中高温」「较高」「一定范围」这类概括词替代
> 具体数字；原文没有的数值不得补写。

抽查根因：`7a50cea3` 原文有 `385±40℃`、`lgf(S2)≈-7.55±1.45`、`251±7℃`，模型概括成
「中高温变质热液」；`5cbe981b` 原文有 `δ56Fe = -2.07‰~+1.58‰`，输出只写 `δ56Fe`。
**文本读得到，是输出侧主动概括**。加了约束后这两篇分别回到 0.88 / 1.00。

`{text}` 在模板最前、指令在末尾，改末尾**不影响前缀缓存**。

注：`key_content` 字面重叠小幅下降（0.648→0.584）是**预期副作用** —— 摘要里塞进了
具体数值，措辞必然变化。该指标只衡量字面相似，不代表质量下降。

#### C4 试过但回退的改动

给摘要/结论区「独立配额 + 顺序全选」（38%/24%），动机是修 `abstract_en` 抓成正文段落
的问题。**实测无收益，已回退**：`abstract_en` 逐字可查 5/6 → 4/6，数值召回
0.902 → 0.898。原因是摘要块的区段判定靠「块累计长度 / 全文长度」近似原文位置，
精度不够，判错的块会挤掉真正的高分块。现维持纯分数竞争（摘要块本身 +6.0 加分）。

`abstract_en` 偶发抓错（16 篇里 1 篇）仍是已知残留问题，根因在 `_segments()` 的区段
识别，留待后续。

#### C5 成本

输入 −32%、输出 +11%，合计**约 −21%**。叠加 A（摘要本地抽，去掉 `abstract_en`
的输出 token）后约 **−29%**。再叠 B（中文字段瘦身、知识点限 3–5 条）预计可到
**−40% 左右**（B 尚未实测）。

| 项 | 状态 | 降本 | 质量影响 |

## 四、上线纪律（不许跳步）

1. **一律开关控制，默认关**：`GEOKB_PREP=headtail`（默认）→ 现行行为逐字节不变；
   `GEOKB_PREP=block` 才走段落级筛选，`GEOKB_BLOCK_BUDGET` 默认 4500。
   `GEOKB_PREP=select` 是已废弃的句级筛选，仅留作对照。
2. **每项单独对拍**：`scripts/_token_saving_ab.py`，基准侧直接读 `state/llm_raw/*.json`（零成本，只跑新版）。
   阈值：字段非空率 ≥ 基准 95%、**关键数值召回 ≥ 0.90**、JSON 失败 0。
   **样本池必须固定**（`logs/ab_pool.json`）：首版实现随 `--n` 重新抽样，
   导致 4500 的召回 0.682 反而低于 3200 的 0.753，纯属样本差异。已修正。
3. **指标必须重算一次再下结论**：`scripts/_ab_recalc.py`（读已存输出，零 API 成本）。
   已抓到两个系统性误判：
   - `ov_key` 用 `[a-z]` 词集 → **中文篇目永远算 0.00**，被误读成质量崩塌（0.478 → 0.648）；
   - 数值比对用原始字符串 → `0.60` ≠ `0.6`，造成假漏。
4. **不过阈值就回退**，不许为省钱放宽阈值。C4 的摘要配额改动就是这样回退的。
5. 已入库 1,048 篇**不重跑**。

> 指标口径注意：`\d+ + 单位` 的朴素正则会跨词误匹配（如 `May 2016` → `201Ma`），
> 必须用 `(?<![A-Za-z0-9])` 词边界 + 单位独立成词，否则召回率算不准。

## 五、明确不做的事

- **合并两次调用为一次**：知识点输入已 95% 命中、只占 1% 成本，合并省不到 3%，却让单次输出扛两套 schema，JSON 截断风险上升。
- **继续调缓存**：第一个任务永远 0 命中，缓存对它无效。
- **换更小模型**：地学数值与术语抽取对模型能力敏感，掉档直接反映在数值准确率。
- **只压预算不问质量**：实测 3,200 预算文本覆盖仅 58%、输出召回更低，属于「省了钱丢了数据」。
